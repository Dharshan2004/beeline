# Use an LLM-centered agentic loop with deterministic guardrails

When model access is available, an LLM is the semantic core of the Shopping Agent: it interprets each turn, proposes Constraint State changes, selects Retrieval Routes and clarifications, and may word the response through an agentic tool loop. Deterministic code supplies the tools and guardrails: it preserves state history in memory under the evaluator's `session_id`, validates proposed mutations, enforces turn and catalog rules, applies the Fusion Policy, rejects invalid outputs, and owns the offline fallback. A connected replacement is valid only when the latest customer turn contains versioned Explicit Replacement Evidence and the same atomic plan establishes a distinct supported successor. One shared deterministic classifier supplies that evidence to both the offline interpreter and connected-plan validator, so the two paths cannot develop different replacement semantics. Attribute-level correction language may replace one unambiguous Constraint but preserves the rest of the Product Intent; replacing the Product Intent requires product-type replacement language or explicit withdrawal of the whole prior intent. An ambiguous product mention is rejected even when the model proposes a replacement. This fail-closed boundary may miss unusual genuine paraphrases, but it prevents model confidence alone from discarding authoritative state. The Turn Plan may select only Candidate Pool-producing Retrieval Routes; local Reranking is a mandatory post-fusion policy when its frozen worker is available and cannot be selected, disabled, or bypassed by the model. No database is required for the competition path. The connected loop always permits one planning call; a second reranking-and-response call is made only when it is expected to improve an ambiguous result, otherwise the local cross-encoder and deterministic response builder complete the turn. Local cross-encoder inference runs in one persistent cancellable worker process so its 1.5-second rerank deadline is an absolute boundary rather than a cooperative check around a blocking model call. The worker loads once; startup failure, crash, malformed output, or a missed deadline returns the fused ordering, terminates the worker when necessary, and disables reranking for the rest of the evaluator run rather than repeatedly paying model-load cost. Provider failure, timeout, invalid structured output, or rejected state transitions trigger a bounded retry and then deterministic takeover. The deterministic interpreter may omit unsupported language and propose every high-confidence supported meaning together, but ambiguous or conflicting state changes produce no mutation; retrieval still uses the last valid Constraint State and the current customer message. Both connected and deterministic Turn Plans pass through the same atomic validator. The committed Turn Plan precedes route selection, fusion, and reranking on every turn, and evaluation replays preserve the planning identity, state revision, selected tools, and conversion eligibility needed to reproduce that trajectory; an Intent Override Target Product cannot count before its replacement Product Intent commits. Model access remains behind a provider-neutral adapter so the agent is LLM-centered without making valid scoring depend on one provider or network availability.
