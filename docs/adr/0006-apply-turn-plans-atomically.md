# Apply Turn Plans atomically

The Shopping Agent will validate a complete Turn Plan against one unchanged Constraint State snapshot and commit all of its transitions together. Each Constraint State has a monotonically increasing revision, and a Turn Plan is accepted only when its expected revision matches; one successful commit increments the revision once, while stale or replayed plans change nothing. If any proposed transition is invalid, none of the Turn Plan is applied; a corrected model attempt or deterministic fallback starts from the original snapshot and must pass through the same validator. Mutation order never resolves contradictions: replacement, dismissal, and reintroduction are explicit transitions, while incompatible operations without an explicit transition are rejected. This rejects potentially useful partial output in exchange for preventing order-dependent, duplicated, or half-applied customer intent from corrupting retrieval.
